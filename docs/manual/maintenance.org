* Plumbing

This section is for contributors.  It describes how the command layer is built
and where to change it.

** EIEIO command classes

Every {{{cmd(bd)}}} subcommand is represented as an EIEIO class defined with
the =beads-defcommand= macro.  A single class definition generates:

1. an EIEIO class with typed slots,
2. CLI argument serialization ({{{fn(beads-command-line)}}}),
3. an auto-generated transient menu derived from slot metadata, and
4. a result type declaration that drives JSON parsing into =beads-types.el=
   objects.

Class hierarchy: =beads-command= (abstract) → =beads-command-global-options=
(adds =--actor=, =--db=, =--json=) → concrete commands.

Macro keywords include =:cli-command= (override the subcommand string),
=:result= (for example =beads-issue= or =(list-of beads-issue)=), =:json nil=
for commands without JSON (doctor, init), and =:transient= (=t= to
auto-generate, =nil= for none, =:manual= when a hand-written prefix follows in
the same file).

** Execution contract

Command objects are never mutated; execution clones them.  Three generics
dispatch on the command:

- {{{fn(beads-command-execute)}}} :: Synchronous.  Forces =--json=, runs
  {{{cmd(bd)}}}, parses through =beads-from-json=, and returns typed domain
  objects (or a raw string when =:json nil=).  Unit tests mock this.
- {{{fn(beads-command-execute-interactive)}}} :: Entry point for transient
  suffixes.  The default runs the command in a =compilation-mode= buffer;
  commands override it to show or refresh a buffer.
- {{{fn(beads-command-execute-async)}}} :: Non-blocking, with =on-success= and
  =on-error= callbacks.  An optional =:queue= applies the concurrency cap and
  =:cache-key= coalesces identical concurrent requests.  The board, eldoc, and
  list loaders use this path.

Errors signal =beads-validation-error=, =beads-command-error=, or
=beads-json-parse-error= (hierarchy in =beads-error.el=).

** The command bridge protocol

=beads-defcommand= and =beads-meta-define-transient= generate menus whose
execute and preview suffixes call exactly three generic functions.  These are
the supported extension contract for a consumer package that defines its own
command base class:

- =beads-command-validate (command)= :: Return an error string (or list) when
  the command is invalid, or nil when it is valid.
- =beads-command-execute-interactive (command)= :: Run the command and present
  the result.
- =beads-command-preview (command)= :: Return the command line that would run,
  without running it.

#+BEGIN_SRC emacs-lisp
(defclass my-command (beads-command-global-options) ()
  :abstract t
  :documentation "Base class for my-tool commands.")

(cl-defmethod beads-command-validate ((cmd my-command)) ...)
(cl-defmethod beads-command-execute-interactive ((cmd my-command)) ...)
(cl-defmethod beads-command-preview ((cmd my-command)) ...)
#+END_SRC

* Extending beads.el

beads.el is meant to be reused as a library.  The entry points below are
supported and their signatures are kept stable; prefer them over the private
(=beads--=) symbols, which may change without notice.

** Macro-expansion helpers

The pure helpers =beads-defcommand= uses at macro-expansion time are public:

- =beads-meta-extract-option= :: Pull a keyword's value out of a =defclass=
  options plist.
- =beads-meta-derive-transient-name= :: Derive a transient name from a class
  name.
- =beads-meta-first-sentence= :: First sentence of a docstring, for a
  transient short-doc.
- =beads-meta-current-feature-name= :: Feature name of the file being
  processed, for autoload forms.

** Section buffers and the mode-inheritance idiom

Derive a major mode from =beads-section-mode= and parent its keymap:

#+BEGIN_SRC emacs-lisp
(defvar-keymap my-section-mode-map
  :parent beads-section-mode-map
  "RET" #'my-visit-thing-at-point)

(define-derived-mode my-section-mode beads-section-mode "My"
  "Major mode for my-tool section buffers."
  :interactive nil)
#+END_SRC

** Thing motion

A /thing/ is a run of text carrying the =beads-thing= text property; in a
=tabulated-list-mode= buffer every row is one.  The value is a toggle
function, a plist =( :kind KIND :toggle FN )=, or any other non-nil value.

#+BEGIN_SRC emacs-lisp
(beads-thing-define-keys my-section-mode-map) ; TAB, S-TAB, SPC, DEL/S-SPC

(beads-thing-propertize "Agents  3 running"
                        (list :kind 'section :toggle #'my-fold))
(add-hook 'beads-thing-toggle-functions #'my-toggle-drawer nil t)
#+END_SRC

=beads-thing-forward= and =beads-thing-backward= move and wrap (echoing
=Wrapped=).  =beads-thing-toggle= calls the thing's own toggle, then the
buffer-local =beads-thing-toggle-functions=, then pushes the button at point
for kinds =section= and =fold=.

** Reusable pagination

=beads-pager= exposes a pure, buffer-agnostic pagination core:

- =beads-pager-window-page-size (&optional window)= :: Rows that fit a window,
  with a floor of five.
- =beads-pager-page-count (total page-size)= :: Number of pages.
- =beads-pager-page-bounds (page page-size total)= :: =(START . END)= indices,
  clamped to total.
- =beads-pager-slice (entries page page-size)= :: The sublist for a page.

These read no buffer-local state; =beads-pager-mode= is built on the same
core.

* FAQ

** Why does beads.el require the {{{cmd(bd)}}} CLI?

beads.el is a frontend.  All data operations go through {{{cmd(bd)}}}, which
manages the Dolt database, so the Emacs UI and command-line workflows always
agree.

** How do I use beads.el with remote projects?

Open beads.el from a TRAMP directory and it acts on that host's store.
Synchronous commands use =process-file=.  Asynchronous reads on a single-hop
ssh-family method run as local {{{cmd(ssh -T)}}} processes that =cd= to the
store, so they never block Emacs and never share TRAMP's pty-backed master.
ssh runs in BatchMode, so key or agent authentication is required.  Opening,
rendering, and folding a view perform no file access over TRAMP.

** How do I add a command that is not covered yet?

Define a =beads-defcommand= class in a new =beads-command-<name>.el= file and
declare its result type; the CLI serialization, transient menu, and JSON
parsing are derived from the slot metadata.  See [[*Plumbing]].

** Where do I report a bug?

Use the tracker for the {{{cmd(bd)}}} CLI for data problems and the beads.el
tracker for UI problems.  Include {{{kbd(M-x beads-version)}}} output for
version skew.
