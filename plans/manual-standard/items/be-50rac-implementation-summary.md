# Implementation Summary — be-50rac (WI-07: Command and Variable Reference)

## Summary

WI-07 fills `doc/reference.texi` with the complete Command and Variable
Reference chapter (REQ-008, REQ-009). The chapter is machine-derived from
the documented dispatch contract and the `lisp/` sources, so its inventory
is deterministic and can be gated by WI-08 without re-deriving the rule.

The derivation rule is pinned in the `BEGIN GENERATED` comment at the head
of `doc/reference.texi` and has exactly three parts:

1. **Commands.** Let `ROOTS` be `beads-dispatch-doc-menus` (the four
   hand-written dispatch prefixes). Walk them with
   `beads-transient-doc-suffixes`, recursing into every suffix whose
   `:command` is itself a transient prefix. Each distinct reachable command
   gets one `@deffn` entry; when the command also defines `NAME--execute`
   (the suffix `beads-defcommand` generates) it gets an additional
   `@deffn NAME--execute` entry.
2. **Keybindings.** Every `:key` returned over the reachable prefixes is a
   row in the Keybinding Reference, rendered with its full key path and
   grouped by the top-level menu group that holds it.
3. **User options.** Every symbol under `lisp/` for which
   `custom-variable-p` is non-nil gets exactly one `@defopt` entry.

## Intended Behavior

- **REQ-008 (complete coverage).** Every user-visible command and every
  user option has exactly one indexable reference entry. The inventory
  covers all four documented dispatch roots and their nested prefixes; it
  deliberately excludes the ~264 internal `beads-defcommand` classes that
  are not reachable from a documented menu, so no private/internal class is
  forced into the reference. The `--execute` suffix generated by
  `beads-defcommand` is documented for every command that defines it.
- **REQ-009 (cross-references and index).** The chapter is reachable from
  the Top menu and is cross-referenced from every task chapter. `@deffn`
  and `@defopt` auto-populate the `fn` index; `@syncodeindex vr fn` merges
  the variable index into the same `Command and Variable Index`, and
  `@kindex` rows feed the `Key Index`. The `Keybinding Reference` gives the
  full key path to each binding, so no keystroke is orphaned.
- **Single machine-derived source.** The pinned rule is the same input WI-08
  consumes, so the reference and its future completeness gate cannot drift
  apart silently.

## Remaining Risks

- **Keybinding rows are derived independently of the command table.** The
  chapter is internally consistent here, but WI-08 should assert that each
  row's key path still resolves to the documented command; today the
  Keybinding Reference is checked only by construction, not by the
  final-proof diff (which compares command and option inventories).
- **The `--execute` suffix rule uses `fboundp`, not load-time metadata.**
  A command whose `NAME--execute` is autoloaded but not yet defined when
  the reference is generated would be omitted. In this worktree every
  `beads-defcommand` file is loaded before the walk, so the observed set is
  complete; WI-08 should load the same way.
- **Wikidata/WI-06 idiom alignment is not re-verified here.** WI-07 built on
  the WI-05 chapter shell and the current markup; if TODO WI-06 changes
  `@deffn`/`@defopt` presentation conventions, the reference may need a
  mechanical restyle.
