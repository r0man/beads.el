# Implementation Summary — be-87yr2 (WI-08: reference-completeness `:unit` gate)

## Summary

WI-08 adds the reference-completeness `:unit` gate (REQ-008, REQ-009) as
`lisp/test/beads-manual-reference-test.el`. It derives the user-visible
inventory exactly as pinned in the `BEGIN GENERATED` comment at the head
of `doc/reference.texi` (WI-07, be-50rac) and asserts that every name has
a matching `@deffn`/`@defopt` entry in `doc/*.texi`. The derivation and
the reference therefore share one rule, and removing a single entry makes
the gate fail naming the missing command or option.

The pinned rule has three parts, reproduced verbatim by the test:

1. **Commands.** Walk the four documented dispatch menus
   (`beads-dispatch-doc-menus`) with `beads-transient-doc-suffixes`,
   recursing into every suffix whose command is itself a transient prefix.
   Each distinct reachable `beads-*` command gets a `@deffn` entry;
   generated infix pseudo-commands named `transient:...` are ignored.
2. **Execute suffixes.** A reachable command NAME that also defines
   `NAME--execute` (the suffix generated by `beads-defcommand`) gets an
   additional `@deffn NAME--execute` entry.
3. **User options.** Every symbol under `lisp/` for which
   `custom-variable-p` is non-nil gets exactly one `@defopt` entry.

On the WI-07 tree the derivation yields exactly the reference inventory:
**266** reachable commands, **195** generated `--execute` suffixes, and
**166** user options, for **461** `@deffn` plus **166** `@defopt` entries.
The gate compares the inventory against every `doc/*.texi` chapter, so it
also accepts the task chapters' `@deffn` definitions of the view modes
(`beads-dashboard-mode`, `beads-list-mode`, `beads-show-mode`), which are
not part of the command inventory.

Only a test file changed. No `lisp/` runtime file was touched (REQ-017).

## Intended Behavior

- **REQ-008 (complete coverage).** A user-visible command or user option
  cannot exist without a reference entry. The gate walks the same ROOTS
  and the same `custom-variable-p` inventory WI-07 used and fails with the
  list of missing names, mirroring the `scripts/dispatch-docs` drift
  discipline.
- **REQ-009 (bidirectional drift).** In addition to completeness, a fourth
  test asserts that `doc/reference.texi` holds no `@deffn`/`@defopt` entry
  outside the derived inventory, so a renamed or removed command cannot
  leave a stale reference entry behind.
- **Hermetic (`:unit`, no `bd`).** The gate loads the `lisp/` sources for
  their transient layouts and `defcustom` definitions and parses only the
  Texinfo sources. It loads the sources itself, once per process, so the
  result does not depend on test-file load order. No store, database, or
  external tool is touched.

## Remaining Risks

- **Inventory breadth depends on every `lisp/` source loading.** If a
  future file becomes unloadable in batch (for example a hard dependency
  on an optional terminal backend), the walk would shrink and both the
  completeness and no-stale tests would fail. That is the intended
  failure direction, but a new optional backend should keep its top-level
  forms loadable or the gate will flag the new commands as undocumented.
- **`symbol-file`-based option scoping.** Options are attributed to the
  file that defined them; a `defcustom` defined by macro expansion in a
  generated file outside `lisp/` would be invisible. The current tree
  defines all 166 options directly under `lisp/`, so this is latent.
- **Keybinding rows are out of scope.** WI-07's remaining-risk note asked
  WI-08 to assert that each keybinding row resolves to a documented
  command. This gate keeps WI-07's scope (command, `--execute`, and option
  inventories) and does not add a keybinding-row check; that remains a
  possible follow-up rather than a regression.
