## Remaining Risks

- **GUI capture depends on the host stack.** Regeneration needs pgtk Emacs,
  headless `sway`, ImageMagick `convert`, `bd`, `ef-themes`, and the fixture.
  All were present here; a host without them cannot regenerate the images.
- **Shot-order sensitivity of the `show` breadcrumb.** In a full
  `--scope all` run the `show` shot follows the `dashboard` shot, so the
  current buffer is a live dashboard and `beads-show--origin` records it,
  rendering the `↩ Back to dashboard` breadcrumb (frame height 513). In a
  subset run `show` is captured first and the breadcrumb is absent (height
  494). Both variants are internally reproducible for their scope
  (`--verify all` is green), and the committed set matches the canonical
  `--scope all` output. This is pre-existing engine/shot-list behavior
  (WI-8 `0fafaeb7` added the breadcrumb after the images were last captured),
  outside this work item's "do not change the engine" boundary; a follow-up
  could clear the origin between shots if a breadcrumb-free canonical image
  is preferred.
- **The fixture project basename appears in captured buffer names.** The
  dashboard and show images include `beads-fixture.project`; the fixture
  pins a stable basename so the committed images are reproducible.
